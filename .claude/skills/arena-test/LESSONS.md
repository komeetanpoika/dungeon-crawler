# Arena Test Lessons

Read this before every arena test. Append one imperative line when a run teaches something reusable — this file is why run N+1 goes better than run N.

- Launch via `.claude/skills/run-game/driver.mjs` (`launch` → `press`/`ss`/`eval`/`quit`); on WSLg set `DISPLAY=:0`.
- Type the level0 cheat on the title screen one key at a time: `press l`, `press e`, `press v`, `press e`, `press l`, `press 0`.
- `arena-config.json` is re-read on every level0 entry — edit the config and re-enter the arena instead of relaunching Electron.
- Screenshots land in `$SCREENSHOT_DIR` (default `/tmp/shots`) via the driver's `ss` command.
- After any automated run, `git status --porcelain renderer/data/` must be clean (editor autosave hazard) — restore `painter-maps.json` if it changed.
- Fog-of-war hides ring-placed chests/enemies outside the player's FOV in the very first screenshot — a chest not being visible on entry doesn't mean it didn't spawn; either give it explicit `x`/`y` near the player or budget several `press ArrowUp/ArrowLeft` steps (each `press` moves roughly one step) to walk toward it, and expect an aggressive enemy en route to interrupt that walk.
- Driving a fresh `driver.mjs launch` per fight is slow; instead run it once as a background process reading from a growing command file (`touch cmds.txt; ( tail -n +1 -f cmds.txt | node driver.mjs > out.log 2>&1 ) &`, then `echo "cmd" >> cmds.txt` from later Bash calls, poll `out.log`) — one Electron instance serves many arena re-entries via the level0 cheat, and `text <selector>` (e.g. `text #hud-log`, `text #hud-hp-bar`) is a cheap way to poll game state (HUD messages/HP blocks) between screenshots without guessing timing. `quit` can hang after certain menu states — if it does, `pkill -f driver.mjs; pkill -f electron` cleans up fine.
- dragon_boss is very hard to flank for the tail: its facing re-tracks the player continuously at 0.8 rad/s in every state except a committed attack (cone/sweep/tail_windup/tail), and its `core` capsule (~1.5-tile radius, see `capsules.js`) physically blocks player movement once at melee range — once you're touching it, strafing in any direction largely just fails to move you, pinning you to its front. Circling wide (~2-3 tiles, outside the core-block radius but inside `TAIL_REACH` ~3.2 tiles) avoids the pin but 10 attempts across direct/diagonal/wide-strafe/attack-window-dash approaches still never landed the player in `inTailArc` at the instant `attackCooldown` hit 0 — treat tail-strike provocation as a hard, possibly multi-session problem, not a quick check.

# Arena Test Lessons

Read this before every arena test. Append one imperative line when a run teaches something reusable — this file is why run N+1 goes better than run N.

- Launch via `.claude/skills/run-game/driver.mjs` (`launch` → `press`/`ss`/`eval`/`quit`); on WSLg set `DISPLAY=:0`.
- Type the level0 cheat on the title screen one key at a time: `press l`, `press e`, `press v`, `press e`, `press l`, `press 0`.
- `arena-config.json` is re-read on every level0 entry — edit the config and re-enter the arena instead of relaunching Electron.
- Screenshots land in `$SCREENSHOT_DIR` (default `/tmp/shots`) via the driver's `ss` command.
- After any automated run, `git status --porcelain renderer/data/` must be clean (editor autosave hazard) — restore `painter-maps.json` if it changed.
- Fog-of-war hides ring-placed chests/enemies outside the player's FOV in the very first screenshot — a chest not being visible on entry doesn't mean it didn't spawn; either give it explicit `x`/`y` near the player or budget several `press ArrowUp/ArrowLeft` steps (each `press` moves roughly one step) to walk toward it, and expect an aggressive enemy en route to interrupt that walk.
- Driving a fresh `driver.mjs launch` per fight is slow; instead run it once as a background process reading from a growing command file (`touch cmds.txt; ( tail -n +1 -f cmds.txt | node driver.mjs > out.log 2>&1 ) &`, then `echo "cmd" >> cmds.txt` from later Bash calls, poll `out.log`) — one Electron instance serves many arena re-entries via the level0 cheat, and `text <selector>` (e.g. `text #hud-log`, `text #hud-hp-bar`) is a cheap way to poll game state (HUD messages/HP blocks) between screenshots without guessing timing. `quit` can hang after certain menu states — if it does, `pkill -f driver.mjs; pkill -f electron` cleans up fine.
- dragon_boss is very hard to flank for the tail: its facing re-tracks the player continuously at 0.8 rad/s in every state except a committed attack (cone/sweep/tail_windup/tail), and its `core` capsule (~1.5-tile radius, see `capsules.js`) physically blocks player movement once at melee range — once you're touching it, strafing in any direction largely just fails to move you, pinning you to its front. Circling wide (~2-3 tiles, outside the core-block radius but inside `TAIL_REACH` ~3.2 tiles) avoids the pin but 10 attempts across direct/diagonal/wide-strafe/attack-window-dash approaches still never landed the player in `inTailArc` at the instant `attackCooldown` hit 0 — treat tail-strike provocation as a hard, possibly multi-session problem, not a quick check.
- To reach the tail arc, orbit the boss continuously at 2-3 tiles: player angular speed (~1.5 rad/s at that radius) out-turns TURN_RATE 0.25 about 6:1; standing still lets the boss face you out of the arc in ~5s.
- One unreproduced permanent freeze is on file (frame missing the boss rig, page alive, right after a point-blank tail hit): if it happens again, capture the DevTools console BEFORE closing the window — an exception inside drawDragonBoss would kill the rAF loop exactly like that.
- For continuous player movement use `eval (window.dispatchEvent(new KeyboardEvent('keydown',{key:'ArrowUp'})), 'ok')` and a later keyup — discrete `press` steps are far slower than enemies and a glued melee enemy kills a scripted player in seconds; chain expressions with the comma operator, never `||` (dispatchEvent returns true and short-circuits the rest).
- Menu navigation is stateful and dangerous: arrow keys pressed during gameplay also move death/pause menu focus, Enter on the death screen may hit "Quit to Title", and Down-Down-Enter on the TITLE menu hits Quit and closes Electron — after any death, prefer relaunching or screenshot the menu before pressing Enter.
- "Play Again" from the level-0 death screen restarts at depth 1, and the level0 cheat only parses on the TITLE screen — the in-game path back to the arena is Escape → (screenshot to check focus) → Quit to Title → cheat.
- Tap `press` for GAMEPLAY keys (Space, movement) can fall between rAF frames and silently never register — the swing whiffs with no arc drawn. Use eval keydown / sleep 0.2 / keyup for every input that gameplay must observe, not just for continuous movement.
- The arena player config accepts `rangedType` (e.g. `"rangedType": "firewand"`) to spawn already holding any ranged weapon — no chest walk needed; and `#hud-log` renders only the NEWEST message, so poll `text #hud-log` every ~0.4s immediately after the event you care about before glued-enemy hit spam overwrites it.
- Canvas geometry (hitboxes vs. swing animation) is far cheaper to verify with a fake ctx that records the transform matrix at each drawImage than with screenshots — small sprites are easy to misread by eye, while the recorded matrix gives the exact blade angle per facing (see the probeCtx helper in test/melee.test.js).
- Chasers reach the player within a second or two and stand ON the player's tile, so a screenshot of a "solo" player is usually a stack — count the green HP bars above the pile to see how many enemies are really there, and never conclude from a sprite-less screenshot that a configured enemy failed to spawn.
- Never run `pkill -f driver.mjs` (or any pattern matching the driver path) directly from the Bash tool — `pkill -f` matches your own invoking shell's command line and kills it mid-command, losing the rest of the chain. Put the kill + relaunch sequence in a scratchpad `.sh` and run that instead.
- Piping multiple driver commands via a single fast `cat >>`/heredoc into the command FIFO can dispatch them concurrently rather than strictly in order — `readline`'s `'line'` handler is `async` but the driver doesn't await/serialize between lines, and `eval` (page.evaluate) typically resolves faster than `ss` (page.screenshot), so a batch of `eval`s queued ahead of a `ss` can all finish and mutate state before that screenshot actually fires. For before/after comparisons, send one command at a time with a short `sleep` between, not a batch — a screenshot showing state you hadn't added yet in file order is the tell.
- Omitting `enemies` from `arena-config.json` does NOT give an empty arena — it still spawns the default dragon boss. Use an explicit `"enemies": []` to get a genuinely safe, empty room for scripted state-injection tests that shouldn't risk player death mid-script.
- To read/mutate live game state (not exposed on `window` by default) from the driver's `eval`, add a throwaway one-liner like `window.__debugState = state` inside `render()` (or wherever the module-scoped state variable updates), run your checks, then remove the line before committing — grep the final diff to confirm it's gone.
- The rite/ceremony renderer can be exercised in the empty arena by injecting `state.rite` via the __debugState hook — no overworld trek needed; check running processes with `pgrep -a node` (a bare `pgrep -f <driver-path>` matches the invoking shell and reports a false "still running").
- KeyboardEvents dispatched ON window collapse to at-target phase: every window listener fires in registration order and stopPropagation cannot stop them — a capture-phase panel handler will NOT shield the keys[] tracker from eval-dispatched keys the way it does for real (body-targeted) key presses; make close paths clear the relevant keys[] entry.
- game.js already exposes a built-in debug hook — no need for the line-25 `window.__debugState` hack. Launching Electron with an extra `'--dcdebug'` arg (main.cjs passes it through as `?dcdebug=1`) sets `window.__dc = { get state() { return state } }`, giving read-only live access to `window.__dc.state.player.{px,py,facing}` and `window.__dc.state.entities.map(e=>({hp:e.hp,px:e.px,py:e.py}))` — invaluable for confirming exact positions/facing/hp without guessing from screenshots. driver.mjs hardcodes its launch args without this flag, so copy it to a throwaway script (adjust the `args` array to add `'--dcdebug'`) rather than editing the shared one; delete the copy when done and confirm `git status --porcelain` is clean.
- Melee hit regions are facing-relative ("in front of the player"), and the default spawn facing (e.g. 'south') rarely matches an enemy's actual approach side — a glued-looking enemy can still make every swing whiff with no visible error. Use the `--dcdebug` hook above to read the real relative position, then tap the single directional key that points toward the target immediately before swinging.
- A non-charge weapon (not in melee.js's CHARGE map, e.g. sword) swings every frame `attacking` (key held) is true and its cooldown has expired — holding the key for even ~1-3s of real wall-clock time (typical Bash-tool round-trip latency between separate keydown/keyup calls) fires several swings, easily overkilling a low-HP monster before you can observe one non-lethal hit. For a single clean hit, use the driver's atomic `press Space` (not manual keydown+keyup across two calls).
- The hit-flash window is only ~180ms (HIT_FLASH in monsters.js) and screenshot round-trips are usually slower than that, so a screenshot taken after a separate `press`/`eval` call routinely arrives after the flash already faded — even though the same-batch fast-dispatch ordering issue (lesson above: `eval` resolving before `ss`) is the opposite failure mode. What worked: queue `press Space` immediately followed by 1-2 `ss` lines in the same batch — the same-batch `eval`/`press` resolving faster than `ss` meant the post-hit HP was already updated before the screenshot fired, and the first screenshot still caught the flash frame.
- To detect a hit-flash (or any specific fillStyle) precisely instead of guessing screenshot timing, monkeypatch `CanvasRenderingContext2D.prototype.fill` via `eval` to push `performance.now()` into a `window.__flashLog` array when `this.fillStyle` matches — pure runtime, no file edits, safe to leave for the rest of the session.
- "Restart" on the pause menu (Escape → ArrowDown×1 → Enter, from the Resume/Restart/Quit-to-Title list) respawns the same arena-config.json layout instantly, cheaper than quitting to title and re-typing the level0 cheat.
- Podeboo's burst flash is 0.25s — poll at <=0.2s intervals or force sweep mode (eval e.hp <= maxHp/2) to catch beams; its glued-chaser touch damage kills an unprotected player in ~15s, so eval player.invulnTimer=99999 IMMEDIATELY after arena entry; and never chain anything after a pkill whose pattern can match your own background driver pipeline — the pkill killed this session's shell mid-chain despite living in a scratchpad script.
- Leap episodes start the player UNARMED (empty kit) and story creatures only spawn from their episode's own trigger, so before any live creature check set `state.player.weapon = { weaponType:'sword', name:'Sword', damage:2, chop:1 }` and push the creature yourself with `state.epCtx.spawn([{ kind, x, y }])` — setting the story flag alone (e.g. `bell_hung`) spawns nothing, since `onArrive` already ran. Reach depth 10 through the title's Timewarp → episode list, never the `level10` cheat.
- Sample fast creature transitions (sink/erupt/burn/dying) with an in-page `setInterval` pushing frames into `window.__nlog` and read it back in one `eval` — per-call polling round-trips (~1s) miss whole phases, and remember the sack/pause overlay FREEZES the loop, so a log of identical rows means a panel is still open (`document.body.innerText` tells you), not a stuck creature.

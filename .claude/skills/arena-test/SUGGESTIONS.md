# Arena Test Suggestions

Feature ideas harvested from test runs (`arena-log.mjs suggest`). Format: `- [NEW|DONE] date (run N): suggestion`. Flip NEW → DONE when implemented.
- [NEW] 2026-07-03 (run 1): Single-chest auto-placement always lands at ring index 0 (top-left corner), which sits outside the player's starting FOV in a default-sized arena and is guarded by an aggressive cyclops's attack path — makes chests hard to verify visually without walking into enemy range. Consider seeding auto-chest ring start near the player's spawn, or documenting in SKILL.md that testers should give explicit x/y to chests they need to see on screen.
- [NEW] 2026-07-03 (run 2): Provoking the dragon_boss tail strike via manual arena play is very hard: facing continuously re-tracks the player outside attack-committed states (0.8 rad/s), and the core capsule (~1.5-tile radius) blocks player movement once at melee range, pinning the player to the front and preventing the lateral repositioning needed to reach the rear arc. Consider either (a) an arena-config debug knob to force/preview enemy state (e.g. start the boss in tail_windup) for isolated visual QA, or (b) documenting a known-working flank route/technique in LESSONS.md once someone finds one - none of the approaches tried this run (direct, diagonal, wide-radius strafe, attack-window dash) succeeded in 10 attempts.
- [NEW] 2026-07-05 (run 4): Arena could use a player invulnerability flag (e.g. player.invulnerable: true) for movement/AI observation tests — enemy DPS kills a scripted player in seconds and forces test redesign around survival instead of the actual question
- [NEW] 2026-07-05 (run 6): Guard DPS in sustained contact (~2-3 hits/s at 1 dmg) melts even overridden 40hp players in ~15s; if more melee-adjacent observation tests are needed, consider an arena option to scale enemy attack cooldowns
- [NEW] 2026-07-05 (run 8): Against a stationary player the crab's grab dominates so thoroughly that orbit behavior is hard to observe live; a config toggle disabling enemy attacks (observation mode) would isolate movement AI cleanly
- [NEW] 2026-07-06 (run 9): Enemy contact DPS makes multi-enemy melee observation brutal under command-file latency; the observation-mode/invulnerable-player arena flag suggestion from the pathfinding session would have saved 3 deaths here too
- [NEW] 2026-07-24 (run 10): Move Run 9's eval-keydown-holds lesson into SKILL.md setup steps — Run 10 relearned it from scratch and burned most of its budget doing so.
- [NEW] 2026-07-24 (run 11): Document the player rangedType config field in the arena-test SKILL.md syntax block (supported in game.js since ranged rework, used by runs 10-11, absent from docs)
- [NEW] 2026-08-14 (run 12): Arena enemies configured with explicit x/y did not appear at those tiles across three level-0 entries (spawned elsewhere or never drawn, while still attacking) - worth a dedicated run to check whether arena-config.json is re-read on every cheat entry and whether depth-0 FOV marks enemy tiles visible, since 'place an enemy exactly here' is the backbone of any combat-geometry test.
- [NEW] 2026-08-15 (run 12): CORRECTION to the previous suggestion (run 12): arena-config.json IS read and explicit enemy x/y ARE honoured. The 'missing' enemies were chasers that had already converged onto the player's tile and stacked there — in a screenshot the pile reads as one sprite, and the giveaway is the extra green HP bars above it. A later run that showed the default dragon-boss arena was my own error (the config file had not been written). Count HP bars, not sprites.
- [NEW] 2026-08-15 (run 13): Arena needs a way to freeze enemy AI (e.g. a top-level "paused": true or "frozen": true flag) for pure rendering/visual checks. Two bosses spawned for a side-by-side comparison converged on the player within ~3s and overlapped into an unreadable pile, and even a single boss closes to melee before you can frame a clean shot; every visual check currently races the AI.
- [NEW] 2026-08-23 (run 15): An arena-config option to pre-grant/trigger a rite (or a generic 'inject state' field) would avoid the temporary window.__debugState hook edit in game.js
- [NEW] 2026-08-31 (run 18): The melee hit region is facing-relative, but nothing in the arena-test tooling exposes facing or precise entity px/py without relaunching with --dcdebug (a separate driver script, since driver.mjs hardcodes launch args). Consider either exposing __dc regardless of the flag when arena-config.json is present (level0 is already a test-only path) or adding a 'launch --dcdebug' variant to driver.mjs, so melee/hit verification doesn't require hand-rolling a second Electron launcher.
- [NEW] 2026-08-31 (run 19): arena-config player flag like invulnerable:true applied at spawn would beat racing an eval'd invulnTimer against an in-flight attack

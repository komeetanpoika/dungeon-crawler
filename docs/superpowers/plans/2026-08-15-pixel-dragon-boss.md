# Pixel-Art Dragon Boss Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Render the dragon boss from a sheet of individual pixel-art part sprites, developed on a copy that spawns in the level-0 test arena while the shipped depth-5 boss keeps rendering exactly as it does today.

**Architecture:** The boss entity keeps its type (`dragon_boss`) and gains a `skin: 'pixel'` field, so AI, hitboxes, damage and immunities are shared rather than duplicated — only one line in `canvas.js` branches. A bake script renders each part out of the existing vector renderer in isolation, palette-quantises it, and packs a sprite sheet plus a generated frame table. A new renderer composites the parts into a single low-resolution offscreen buffer and blits it up with nearest-neighbour, so every rotated part lands on one shared pixel grid. The rig → part-placement math is a pure function, separate from the drawing, so it can be unit tested without a canvas.

**Tech Stack:** Vanilla ES modules (no bundler), `node:test` + `node:assert/strict`, `playwright-core` (already a devDependency) for the offline bake, `node:zlib` for a dependency-free PNG reader used by asset tests.

**Design doc:** `docs/superpowers/specs/2026-08-15-pixel-dragon-boss-design.md`

**Art scale note:** `ART_PX` is screen pixels per art pixel **at `S = 32`**. Its
source of truth is `tools/bake-dragon-parts.mjs`; `renderer/data/dragon-parts.js`
re-exports it as generated output, so editing it there is overwritten by the next
bake. Every sprite dimension is derived from it. The plan uses `ART_PX = 4`. The
rest of the game's tileset is 16×16 source drawn into a 32px tile, i.e. the
equivalent of 2 — switching is a one-line edit in the bake plus a re-bake, and no
dimension is hard-coded anywhere else.

Because `ART_PX` is pegged to `S = 32`, runtime code must scale it with the
actual tile size: **`const A = ART_PX * S / 32`**, never a hard-coded `S / 8`
(which silently assumes `ART_PX === 4`).

```js
// Minimal PNG reader: 8-bit, non-interlaced, colour types 0 (grey), 2 (RGB),
// 3 (indexed), 4 (grey+alpha) and 6 (RGBA). Enough to inspect our own sprite
// sheets in tests without taking on a dependency; throws clearly on anything
// else rather than returning wrong pixels.
import { inflateSync } from 'node:zlib'
import { readFileSync } from 'node:fs'

const CHANNELS = { 0: 1, 2: 3, 3: 1, 4: 2, 6: 4 }

function paeth(a, b, c) {
  const p = a + b - c
  const pa = Math.abs(p - a), pb = Math.abs(p - b), pc = Math.abs(p - c)
  return pa <= pb && pa <= pc ? a : pb <= pc ? b : c
}

// Undo the per-row filter in place. `prev` is the already-unfiltered row above.
function unfilter(type, line, prev, ch) {
  for (let i = 0; i < line.length; i++) {
    const a = i >= ch ? line[i - ch] : 0
    const b = prev[i]
    const c = i >= ch ? prev[i - ch] : 0
    let v = line[i]
    if (type === 1) v += a
    else if (type === 2) v += b
    else if (type === 3) v += (a + b) >> 1
    else if (type === 4) v += paeth(a, b, c)
    else if (type !== 0) throw new Error(`unsupported PNG row filter ${type}`)
    line[i] = v & 0xff
  }
}

export function readPng(path) {
  const buf = readFileSync(path)
  if (buf.readUInt32BE(0) !== 0x89504e47) throw new Error(`${path}: not a PNG`)

  let pos = 8
  let width = 0, height = 0, depth = 0, colorType = 0, interlace = 0
  let palette = null, trns = null
  const idat = []
  while (pos < buf.length) {
    const len = buf.readUInt32BE(pos)
    const type = buf.toString('ascii', pos + 4, pos + 8)
    const data = buf.subarray(pos + 8, pos + 8 + len)
    pos += 12 + len                     // 4 len + 4 type + data + 4 crc
    if (type === 'IHDR') {
      width = data.readUInt32BE(0); height = data.readUInt32BE(4)
      depth = data[8]; colorType = data[9]; interlace = data[12]
    } else if (type === 'PLTE') palette = data
    else if (type === 'tRNS') trns = data
    else if (type === 'IDAT') idat.push(data)
    else if (type === 'IEND') break
  }

  if (depth !== 8) throw new Error(`${path}: only 8-bit PNGs supported (got bit depth ${depth})`)
  if (interlace !== 0) throw new Error(`${path}: interlaced PNGs not supported`)
  const ch = CHANNELS[colorType]
  if (!ch) throw new Error(`${path}: unsupported colour type ${colorType}`)

  const raw = inflateSync(Buffer.concat(idat))
  const stride = width * ch
  const out = new Uint8Array(width * height * 4)
  let prev = Buffer.alloc(stride)
  for (let y = 0; y < height; y++) {
    const filter = raw[y * (stride + 1)]
    const line = Buffer.from(raw.subarray(y * (stride + 1) + 1, (y + 1) * (stride + 1)))
    unfilter(filter, line, prev, ch)
    for (let x = 0; x < width; x++) {
      const i = (y * width + x) * 4
      if (colorType === 6) {
        out[i] = line[x*4]; out[i+1] = line[x*4+1]; out[i+2] = line[x*4+2]; out[i+3] = line[x*4+3]
      } else if (colorType === 2) {
        out[i] = line[x*3]; out[i+1] = line[x*3+1]; out[i+2] = line[x*3+2]; out[i+3] = 255
      } else if (colorType === 3) {
        const p = line[x]
        out[i] = palette[p*3]; out[i+1] = palette[p*3+1]; out[i+2] = palette[p*3+2]
        out[i+3] = trns && p < trns.length ? trns[p] : 255
      } else if (colorType === 4) {
        out[i] = out[i+1] = out[i+2] = line[x*2]; out[i+3] = line[x*2+1]
      } else {
        out[i] = out[i+1] = out[i+2] = line[x]; out[i+3] = 255
      }
    }
    prev = line
  }
  return { width, height, pixels: out }
}
```

// The pixel dragon's locked 16-colour palette, derived from the vector boss's
// own colours. Every opaque pixel in assets/tiles/dragon_boss_parts.png must be
// one of these — asserted by test/dragon-parts.test.js, so hand-drawn
// replacements stay on-palette automatically.
// Frozen so "locked" is a runtime guarantee rather than a comment promise —
// the bake serialises this array into a browser context and the conformance
// test reads it back, so a stray mutation would be invisible until the art
// broke.
export const DRAGON_PALETTE = Object.freeze([
  [ 20,   8,   6],   //  0 near-black outline
  [ 42,  13,  10],   //  1 deepest shadow
  [ 58,  18,  13],   //  2 body underlay
  [ 90,  23,  18],   //  3 foot pad / dark scale
  [124,  36,  27],   //  4 scale mid-dark
  [156,  46,  36],   //  5 wing bone
  [184,  58,  44],   //  6 scale mid
  [212,  85,  58],   //  7 scale light
  [239, 138,  90],   //  8 highlight
  [ 86,  21,  16],   //  9 membrane dark
  [146,  48,  40],   // 10 membrane
  [239, 224, 192],   // 11 claw / tooth
  [216, 184, 134],   // 12 horn
  [122,  96,  60],   // 13 horn shadow
  [255, 210,  58],   // 14 eye glow
  [255, 122,  42],   // 15 flame
].map(Object.freeze))

export function rgbKey(r, g, b) { return (r << 16) | (g << 8) | b }

export const PALETTE_KEYS = new Set(DRAGON_PALETTE.map(([r, g, b]) => rgbKey(r, g, b)))

## Task 4: Bake the sprite sheet

The bake renders each part from the **existing** vector renderer in a neutral pose, quantises to the palette, packs a sheet and writes the frame table. It reaches the module's private part functions by re-importing the source with an export appended — the same trick the brainstorming prototypes used — so the bake tracks the shipping art code instead of duplicating it.

**Neutralising transforms** (each part must be baked with its own rotation removed, so placement can apply the real angle):

| Part | Call | Neutralising wrapper |
|---|---|---|
| `body` | `scaleBody(ctx, 3*S, 4*S, S)` | none — already centred at origin |
| `neck0…4` | `shieldScale(ctx, w, S*0.7*1.7, top, bot)` | none — centred, unrotated |
| `tail0…4` | `shieldScale(ctx, w, S*0.8*1.7, top, bot)` | none |
| `tail_tip` | `shieldScale(ctx, max(w5, 3*ART_PX), S*0.8*1.7*2, top, bot)` | none |
| `head` | `head(ctx, {x:0,y:0,ang:-Math.PI/2}, S)` | `ang = -PI/2` makes its internal `rotate(ang + PI/2)` a no-op |
| `wing` | `wing(ctx, 0, 0, 1, T_BAKE, S)` | wrap in `ctx.rotate(flapAt(T_BAKE))` to cancel its internal `rotate(-flap)` |
| `foot` | `foot(ctx, 1, 0, 1, T_BAKE, S)` | wrap in `ctx.rotate(-wig); ctx.translate(-1, 0)` — see below |
| `flame` | `flameCone(ctx, 0, 0, 0, S)` | none — apex at origin, aimed along +x |

where `flapAt(t) = Math.sin(t * 1.5) * 0.12 + 0.22` and `T_BAKE = 0`.

**The foot does not bake at zero wiggle.** `foot()` applies *two* transforms —
`translate(bx, by)` **and** `rotate(wig)` where `wig = Math.sin(t*2.0 + bx)*0.05`.
With `bx = 1, t = 0` that is `sin(1)*0.05 ≈ 0.0421 rad ≈ 2.41°`, not zero.
Cancelling only the translate leaves a 2.41° shear baked into the sprite, which
the placement code then applies a second time. Both must be cancelled, and
`rotate(-wig)` must come **first** so the two translates end up adjacent and
annihilate — verified by reading the resulting transform matrix, which is then
a pure translate+scale with zero shear.

// Bakes the dragon boss's parts out of the EXISTING vector renderer into a
// palette-locked pixel sprite sheet plus a frame table.
//
//   node tools/bake-dragon-parts.mjs            # writes *.generated.* only
//   node tools/bake-dragon-parts.mjs --force    # overwrites the shipped files
//
// The default is deliberately non-destructive: once parts have been redrawn by
// hand, a stray re-run must not silently clobber them.
import http from 'node:http'
import fs from 'node:fs'
import path from 'node:path'
import { fileURLToPath } from 'node:url'
import { chromium } from 'playwright-core'
import { DRAGON_PALETTE } from '../renderer/data/dragon-palette.js'

const ROOT = path.join(path.dirname(fileURLToPath(import.meta.url)), '..')
const FORCE = process.argv.includes('--force')
const ART_PX = 4                       // screen px per art px at S = 32
const S = 32
const T_BAKE = 0

const SHEET_OUT = path.join(ROOT, 'renderer/assets/tiles',
  FORCE ? 'dragon_boss_parts.png' : 'dragon_boss_parts.generated.png')
const TABLE_OUT = path.join(ROOT, 'renderer/data',
  FORCE ? 'dragon-parts.js' : 'dragon-parts.generated.js')

const MIME = { '.js': 'text/javascript', '.html': 'text/html', '.json': 'application/json', '.png': 'image/png' }
const server = http.createServer((req, res) => {
  const p = path.join(ROOT, decodeURIComponent(req.url.split('?')[0]))
  if (!p.startsWith(ROOT) || !fs.existsSync(p) || fs.statSync(p).isDirectory()) { res.writeHead(404); return res.end() }
  res.writeHead(200, { 'content-type': MIME[path.extname(p)] ?? 'application/octet-stream' })
  fs.createReadStream(p).pipe(res)
})
await new Promise(r => server.listen(0, '127.0.0.1', r))
const PORT = server.address().port

const browser = await chromium.launch()
const page = await browser.newPage()
// Same origin as the module server, so the fetch below is not cross-origin.
await page.goto(`http://127.0.0.1:${PORT}/renderer/index.html`)

// Re-import the shipping renderer with its private part functions exposed, so
// the bake can never drift from the art code it is baking.
await page.evaluate(async (url) => {
  const src = await (await fetch(url)).text()
  const patched = src + `\nwindow.__P = { shieldScale, scaleBody, wing, foot, head, flameCone }\n`
  await import(URL.createObjectURL(new Blob([patched], { type: 'text/javascript' })))
}, `http://127.0.0.1:${PORT}/renderer/render/dragonboss.js`)

const { dataUrl, table } = await page.evaluate(({ S, ART_PX, T_BAKE, PALETTE }) => {
  const P = window.__P
  const flapAt = t => Math.sin(t * 1.5) * 0.12 + 0.22

  function quantize(ctx, w, h) {
    const img = ctx.getImageData(0, 0, w, h), d = img.data
    for (let i = 0; i < d.length; i += 4) {
      if (d[i + 3] < 128) { d[i] = d[i + 1] = d[i + 2] = d[i + 3] = 0; continue }
      d[i + 3] = 255
      let best = PALETTE[0], bd = Infinity
      for (const c of PALETTE) {
        const dist = (d[i] - c[0]) ** 2 + (d[i + 1] - c[1]) ** 2 + (d[i + 2] - c[2]) ** 2
        if (dist < bd) { bd = dist; best = c }
      }
      d[i] = best[0]; d[i + 1] = best[1]; d[i + 2] = best[2]
    }
    ctx.putImageData(img, 0, 0)
  }

  // Render `fn` (vector units = screen px) into a wArt x hArt art-pixel canvas
  // whose origin sits at (ox, oy) art px. Returns the canvas and its origin.
  function bake(wArt, hArt, ox, oy, fn) {
    const c = document.createElement('canvas')
    c.width = wArt; c.height = hArt
    const ctx = c.getContext('2d')
    ctx.save(); ctx.translate(ox, oy); ctx.scale(1 / ART_PX, 1 / ART_PX); fn(ctx); ctx.restore()
    quantize(ctx, wArt, hArt)
    return { canvas: c, w: wArt, h: hArt, ox, oy }
  }
  // Convenience: a box of `wPx` x `hPx` screen px centred on the origin, plus
  // 1 art px of margin so anti-aliased edges are not clipped before quantising.
  function centred(wPx, hPx, fn) {
    const w = Math.ceil(wPx / ART_PX) + 2, h = Math.ceil(hPx / ART_PX) + 2
    return bake(w, h, Math.floor(w / 2), Math.floor(h / 2), fn)
  }

  const shade = (front, dk) => [
    `rgb(${(70 + front * 26) * dk | 0},${(22 + front * 12) * dk | 0},${(16 + front * 7) * dk | 0})`,
    `rgb(${(150 + front * 50) * dk | 0},${(56 + front * 24) * dk | 0},${(44 + front * 14) * dk | 0})`,
  ]

  const parts = {}

  // Body — rigid, centred, already unrotated. Extra margin because the scale
  // field deliberately overflows the outline (the scalloped silhouette).
  parts.body = centred(3 * S + 4 * ART_PX, 4 * S + 4 * ART_PX,
    ctx => P.scaleBody(ctx, 3 * S, 4 * S, S))

  // Neck plates — one per joint, widths as in scaledChain's wFn.
  const neckH = S * 0.7 * 1.7
  for (let i = 0; i < 5; i++) {
    const w = S * 0.95 - i * S * 0.07
    const [top, bot] = shade(1 - i / 5, 1.0)
    parts[`neck${i}`] = centred(w, neckH, ctx => P.shieldScale(ctx, w, neckH, top, bot))
  }

  // Tail plates — joints 0..4 only; 5 and 6 are covered by the fused tip.
  const tailH = S * 0.8 * 1.7
  for (let i = 0; i < 5; i++) {
    const w = (7 - i) / 7 * S * 1.2 + 4
    const [top, bot] = shade(1 - i / 7, 0.95)
    parts[`tail${i}`] = centred(w, tailH, ctx => P.shieldScale(ctx, w, tailH, top, bot))
  }
  // Fused tail tip: spans joints 5 and 6, floored at 3 art px wide so it stays
  // drawable (the raw taper would give 3.8 and 2.4 art px).
  {
    const w = Math.max((7 - 5) / 7 * S * 1.2 + 4, 3 * ART_PX)
    const [top, bot] = shade(1 - 5 / 7, 0.95)
    parts.tail_tip = centred(w, tailH * 2, ctx => P.shieldScale(ctx, w, tailH * 2, top, bot))
  }

  // Head — ang = -PI/2 cancels its internal rotate(ang + PI/2). Snout reaches
  // 1.55*S forward, horns 1.3*S back, so bias the origin toward the neck.
  parts.head = bake(
    Math.ceil(1.5 * S / ART_PX) + 2, Math.ceil(2.3 * S / ART_PX) + 2,
    Math.floor((Math.ceil(1.5 * S / ART_PX) + 2) / 2), Math.ceil(1.7 * S / ART_PX),
    ctx => P.head(ctx, { x: 0, y: 0, ang: -Math.PI / 2 }, S))

  // Wing — cancel the rest flap so placement owns the angle. Origin at the
  // shoulder pivot (0,0); the wing extends +x and mostly -y.
  parts.wing = bake(
    Math.ceil(5.2 * S / ART_PX) + 2, Math.ceil(4.2 * S / ART_PX) + 2,
    1, Math.ceil(2.6 * S / ART_PX),
    ctx => { ctx.rotate(flapAt(T_BAKE)); P.wing(ctx, 0, 0, 1, T_BAKE, S) })

  // Foot — bx=1, by=0 forces its outward angle to 0; translate puts the ankle
  // on the origin so placement can rotate it outward.
  parts.foot = bake(
    Math.ceil(3.4 * S / ART_PX) + 2, Math.ceil(3.4 * S / ART_PX) + 2,
    Math.floor((Math.ceil(3.4 * S / ART_PX) + 2) / 2), Math.floor((Math.ceil(3.4 * S / ART_PX) + 2) / 2),
    ctx => { ctx.translate(-1, 0); P.foot(ctx, 1, 0, 1, T_BAKE, S) })

  // Flame cone — apex at the origin, aimed along +x.
  parts.flame = bake(
    Math.ceil(5.4 * S / ART_PX) + 2, Math.ceil(4.0 * S / ART_PX) + 2,
    1, Math.ceil(2.0 * S / ART_PX),
    ctx => P.flameCone(ctx, 0, 0, 0, S))

  // Shelf-pack into a sheet, 1 art px gutter, wrapping at 256.
  const names = Object.keys(parts)
  const MAXW = 256
  let x = 0, y = 0, rowH = 0, sheetW = 0
  const table = {}
  for (const n of names) {
    const p = parts[n]
    if (x + p.w > MAXW) { x = 0; y += rowH + 1; rowH = 0 }
    table[n] = { x, y, w: p.w, h: p.h, ox: p.ox, oy: p.oy }
    x += p.w + 1
    rowH = Math.max(rowH, p.h)
    sheetW = Math.max(sheetW, x - 1)
  }
  const sheetH = y + rowH

  const sheet = document.createElement('canvas')
  sheet.width = sheetW; sheet.height = sheetH
  const sctx = sheet.getContext('2d')
  sctx.imageSmoothingEnabled = false
  for (const n of names) sctx.drawImage(parts[n].canvas, table[n].x, table[n].y)

  return { dataUrl: sheet.toDataURL(), table }
}, { S, ART_PX, T_BAKE, PALETTE: DRAGON_PALETTE })

await browser.close()
server.close()

if (!FORCE && fs.existsSync(path.join(ROOT, 'renderer/assets/tiles/dragon_boss_parts.png'))) {
  console.log('note: shipped sheet left untouched — pass --force to overwrite it')
}
fs.writeFileSync(SHEET_OUT, Buffer.from(dataUrl.split(',')[1], 'base64'))

const order = Object.keys(table)
const rows = order.map(n => {
  const f = table[n]
  return `  ${n.padEnd(10)}: { x: ${f.x}, y: ${f.y}, w: ${f.w}, h: ${f.h}, ox: ${f.ox}, oy: ${f.oy} },`
}).join('\n')

// Frames into renderer/assets/tiles/dragon_boss_parts.png, in art pixels.
// (ox, oy) is the joint the part rotates about, in sprite-local coordinates.

// Screen pixels per art pixel at S = 32. The rest of the tileset is 16x16 in a
// 32px tile, i.e. 2 — 4 is deliberately chunkier. Change here and re-bake.
export const ART_PX = ${ART_PX}

export const SHEET_SPRITE = 'dragon_parts'

export const PARTS = {
${rows}
}

export const PART_NAMES = ${JSON.stringify(order)}
`)

console.log(`wrote ${path.relative(ROOT, SHEET_OUT)} and ${path.relative(ROOT, TABLE_OUT)}`)

```js
// Pixel-art dragon boss. Every part is a sprite from
// assets/tiles/dragon_boss_parts.png, composited into a single low-resolution
// buffer and blitted up with nearest-neighbour — so all rotated parts share one
// pixel grid instead of aliasing independently.
//
// dragonPartPlacements() is pure and holds the whole rig; it mirrors the
// geometry in render/dragonboss.js. Positions are art pixels local to the boss
// centre, -y forward (head), +y back (tail). Facing is NOT applied here: the
// finished buffer is rotated as a unit, which is what keeps the grid coherent.
import { PARTS, SHEET_SPRITE, ART_PX } from '../data/dragon-parts.js'

// Buffer side in art px. Must cover the dragon's full reach: tail ~60 back,
// neck+head ~50 forward, wings ~55 to each side.
const BUF = 160

// Joint positions along a chain, mirroring scaledChain() in dragonboss.js.
function chainPoints(x, y, startAng, segs, segLen, bendFn) {
  let px = x, py = y, ang = startAng
  const pts = [{ x: px, y: py, ang }]
  for (let i = 0; i < segs; i++) {
    ang += bendFn(i)
    px += Math.cos(ang) * segLen
    py += Math.sin(ang) * segLen
    pts.push({ x: px, y: py, ang })
  }
  return pts
}

export function dragonPartPlacements(e, S) {
  const A = ART_PX * S / 32             // screen px per art px at this tile size
  const t = e.breathTime ?? 0
  const bw = 3 * S, bh = 4 * S
  const out = []
  // Positions arrive in screen px and land on whole art px — the snap is what
  // stops parts jittering off the grid between frames.
  const put = (part, x, y, ang, flipX = false) =>
    out.push({ part, x: Math.round(x / A), y: Math.round(y / A), ang, flipX })

  // Feet — bottom layer, claws fanning outward from the body centre.
  for (const [fx, fy, tOff] of [[-0.40, -0.16, 0], [0.40, -0.16, 0],
                                [-0.38, 0.22, 1], [0.38, 0.22, 1]]) {
    const x = bw * fx, y = bh * fy
    const outward = Math.atan2(y, x)
    const wig = Math.sin((t + tOff) * 2.0 + x) * 0.05
    put('foot', x, y, outward + wig)
  }

  // Tail — 7 joints; plates 0..4 are their own sprites, joints 5 and 6 are
  // covered by the single fused tip.
  const sweep = e.tailSwing ?? 0
  const tail = chainPoints(0, bh * 0.46, Math.PI / 2, 7, S * 0.8,
    i => Math.sin(t * 2.2 - i * 0.7) * 0.18 + sweep * (i + 1) / 7 * 0.45)
  for (let i = 0; i < 5; i++) {
    const a = tail[i], b = tail[i + 1]
    put(`tail${i}`, (a.x + b.x) / 2, (a.y + b.y) / 2, b.ang - Math.PI / 2)
  }
  put('tail_tip', (tail[5].x + tail[7].x) / 2, (tail[5].y + tail[7].y) / 2,
      tail[7].ang - Math.PI / 2)

  // Neck — 5 joints, drawn below the body so the body overlaps its base.
  const rear = e.neckRear ?? 0
  const aim = (e.state === 'sweep') ? (e.headAim ?? 0) : 0
  const neck = chainPoints(0, -bh * 0.46, -Math.PI / 2, 5, S * 0.7, i => {
    const idle = Math.sin(t * 0.9 - i * 0.6) * 0.22
    const rearBend = rear * (i < 2 ? 0.55 : -0.65)
    const aimBend = (i === 4 ? aim * 0.9 : aim * 0.15)
    return idle * (1 - rear * 0.6) + rearBend + aimBend
  })
  for (let i = 0; i < 5; i++) {
    const a = neck[i], b = neck[i + 1]
    put(`neck${i}`, (a.x + b.x) / 2, (a.y + b.y) / 2, b.ang - Math.PI / 2)
  }

  // Body — rigid. The vector version breathes by scaling ±2%, which would
  // destroy the pixel grid; here it bobs by a whole art pixel instead.
  const bob = Math.sin(t * 1.4) > 0 ? A : 0
  put('body', 0, bob, 0)

  // Breath cone, then the head, on top of the body.
  const tip = neck[neck.length - 1]
  if (e.state === 'cone' || e.state === 'sweep') put('flame', tip.x, tip.y, tip.ang)
  put('head', tip.x, tip.y, tip.ang + Math.PI / 2)

  // Wings last — the top layer. The sheet holds the right wing; the left is
  // the same sprite mirrored.
  const flap = Math.sin(t * 1.5) * 0.12 + 0.22
  const shoulderY = -bh * 0.22
  put('wing', -bw * 0.12, shoulderY, flap, true)
  put('wing', bw * 0.12, shoulderY, -flap, false)

  return out
}

let sharedBuffer = null
function getBuffer() {
  if (!sharedBuffer) {
    sharedBuffer = document.createElement('canvas')
    sharedBuffer.width = BUF
    sharedBuffer.height = BUF
  }
  return sharedBuffer
}

export function drawDragonBossPixel(ctx, e, camX, camY, S, sprites, buffer) {
  const sheet = sprites?.[SHEET_SPRITE]
  if (!sheet) return                    // sheet missing: draw nothing, never throw
  const A = ART_PX * S / 32
  const buf = buffer ?? getBuffer()
  const half = BUF / 2
  const bctx = buf.getContext('2d')
  bctx.clearRect(0, 0, BUF, BUF)
  bctx.imageSmoothingEnabled = false

  for (const p of dragonPartPlacements(e, S)) {
    const f = PARTS[p.part]
    if (!f) continue
    bctx.save()
    bctx.translate(half + p.x, half + p.y)
    bctx.rotate(p.ang)
    if (p.flipX) bctx.scale(-1, 1)
    bctx.drawImage(sheet, f.x, f.y, f.w, f.h, -f.ox, -f.oy, f.w, f.h)
    bctx.restore()
  }

  const ox = Math.round((e.px ?? (e.x * S + S / 2)) - camX)
  const oy = Math.round((e.py ?? (e.y * S + S / 2)) - camY)
  ctx.save()
  ctx.imageSmoothingEnabled = false
  ctx.translate(ox, oy)
  ctx.rotate((e.facing ?? 0) + Math.PI / 2)
  ctx.drawImage(buf, -half * A, -half * A, BUF * A, BUF * A)
  ctx.restore()
  // No manual smoothing reset: imageSmoothingEnabled is part of the canvas
  // drawing state, so the save/restore above already handles it — and this
  // game's canvas-wide default is `false` (canvas.js sets it in the
  // constructor and in resize()), so forcing it back to `true` here would
  // blur every sprite drawn after the boss.
}
```

Nothing is re-exported from here. `ART_PX` belongs to
`renderer/data/dragon-parts.js`; re-exporting it would give callers a second
place to import the same constant from, and `BUF` is a private detail of the
compositing buffer.

## Findings from the bake (Task 4), carried forward

- **The flame cone sprite is 25% short.** The vector cone is `len = S*5.2`
  (41.6 art px ≈ 5.2 tiles); the baked sprite reaches 31 art px (≈3.9 tiles)
  because its gradient fades to `alpha 0.05` and the `< 128` cutoff erases the
  far third. The *damage* cone is `CONE_LEN = 6 * TILE`, so the player would
  judge safety from a flame visibly shorter than the hitbox — a legibility
  regression, not just an aesthetic one. A fade-to-transparent gradient does not
  translate to a 16-colour pixel sprite at all; the flame wants a hard-edged
  shape at full length. Fix before the pixel boss replaces the real one.
  **Coupled to `BUF`:** measured worst-case reach puts the flame at 75.8 art px
  against the 80 px half-buffer — about 4 px of headroom, and only because the
  sprite is short. Redrawing it to full length lands it near 85 and it gets
  silently clipped, with no test to catch it. Grow `BUF` in the same change.
- **The foot's claws lose their taper.** `pw = S*0.1` is 0.8 art px, below the
  alpha cutoff, so the claws reach 8 art px instead of `S*1.55` (12.4). Pure
  hand-refinement territory; no gameplay consequence.
- **Only the body bobs, so it slides against the neck root.** The vector boss
  breathes by scaling `bw`/`bh` (`1 + breath*0.02`), which moves the chains,
  feet and wings together. The pixel rig cannot scale without destroying the
  grid, so the body alone shifts 1 art px — meaning it moves ~1 px relative to
  the static neck base once per breath cycle. Judge it in the arena (Task 8):
  if it reads as a seam, dropping the bob entirely is better than a detached
  body.
- **Reference sizes must be measured, not guessed.** Both frame sizes quoted
  from the prototype (`body` 34×42, `head` 30×34 with origin 26) clip the art —
  the body's top scale row sits 25 art px above the origin once `bowPx = S*0.6`
  and the rotated plate's own half-height are accounted for, and the head's
  swept-back horns reach 10 art px below it. Size from measured reach.

## Known follow-ups (deliberately not in this plan)

- **Hand-refining the baked parts.** The sheet ships mechanically baked. Redrawing a part means editing `dragon_boss_parts.png` in a pixel editor (8-bit PNG only — the reader rejects other bit depths) and adjusting that part's frame in `renderer/data/dragon-parts.js` if its size changes. The palette and partial-alpha tests will catch off-palette or soft-edged pixels.
- **Art scale.** If the ×4 grid reads as too blocky beside the 16×16 tileset, change `ART_PX` in `tools/bake-dragon-parts.mjs` to 2 and re-run with `--force`. Every dimension is derived, so nothing else changes.
- **`PART_FRAMES` hook.** The design allows a state to opt into hand-authored frames instead of the rig. That hook is not built here — it is a small addition to `dragonPartPlacements` once there is art that needs it.
